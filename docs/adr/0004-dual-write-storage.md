# Dual-write storage, newest-timestamp-wins

Status: Accepted; amended 2026-08 and 2026-11 below. The storage module named below now lives in `platform/storage.js`.

Device-local storage is the whole persistence story after ADR 0001, but localStorage alone is evictable (iOS WebView storage pressure) and IndexedDB alone is async and clunkier to debug — so ticket 04 introduces one storage module that writes every save to both localStorage and IndexedDB, and reconciles at boot by newest `_ts` wins. This generalizes the pattern the mobile build already uses for its Capacitor file mirror (debounced write, hidden-flush, `_ts` comparison), keeps a human-readable copy for debugging/backup, and makes the storage decision the app's single new tested seam (in-memory fakes in tests). Consequence: all persistence goes through this one module; code that touches `localStorage` directly elsewhere is a bug.

2026-08 amendment: the module owns the protocol end-to-end — `_ts` stamping, the shared debounce, flush-on-hidden, boot reconcile and mirror seeding all live in `lib/storage.js` behind `save`/`flush`/`load`/`registerSink`, and the store supplies only app-side facts (running state, `hasData`, DEF overlay). Mirrors plug in as sinks (`{id, read, write}`); the Capacitor file mirror registers from `main.jsx`. Boot tie rules are frozen per platform: mobile file wins ties (`>=`), web keeps the running copy on a tie (`>`).

2026-11 amendment: the reason above was wrong. IndexedDB lives in the same origin storage as localStorage, and WebKit evicts them together (after 7 days without interaction for sites not on the Home Screen, or under storage pressure). The web mirror is cheap insurance against a single-store fault such as a failed or cleared localStorage write, not protection against eviction. The native file mirror is the durable copy. Boot now calls `navigator.storage.persist()` on web (feature-detected, never blocking), and a failed mirror write is recorded (`isMirrorFailing()`) instead of being swallowed.
