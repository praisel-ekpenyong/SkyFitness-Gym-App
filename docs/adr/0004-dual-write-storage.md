# Dual-write storage, newest-timestamp-wins

Device-local storage is the whole persistence story after ADR 0001, but localStorage alone is evictable (iOS WebView storage pressure) and IndexedDB alone is async and clunkier to debug — so ticket 04 introduces one storage module that writes every save to both localStorage and IndexedDB, and reconciles at boot by newest `_ts` wins. This generalizes the pattern the mobile build already uses for its Capacitor file mirror (debounced write, hidden-flush, `_ts` comparison), keeps a human-readable copy for debugging/backup, and makes the storage decision the app's single new tested seam (in-memory fakes in tests). Consequence: all persistence goes through this one module; code that touches `localStorage` directly elsewhere is a bug.
