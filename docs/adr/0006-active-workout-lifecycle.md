# Active-workout lifecycle behind a named seam

Inline mutators across `sheets.jsx` and `views/Workout.jsx` owned the riskiest Profile writes — building the Active workout, confirming working weight, finishing a Workout with Record detection and the heaviest-ever (`exWeights`) merge — with three divergent merge policies (always-max/today at `sheets.jsx:915`, only-if-heavier/workout-date at `:1003`, newer-date-wins reading all sets at `lib/import-csv.js:536`) and a duplicated best-weight read (`Workout.jsx:69` = `sheets.jsx:898`). A phantom second argument `update(mut, true)` at `Workout.jsx:185,218` survived unnoticed.

Fix: `lib/active-workout.js` is the one deep module for this lifecycle, behind named store actions `beginSession` / `recordWorkingWeight` / `finishSession` and a single read seam `bestKnownWeight(S,id)`. The module owns: target freezing, `nextPrescription`/`buildSets`/`applyPrescription`, `heaviestSetWeight`/`heaviestForEntry` (warm-ups and unticked sets excluded, `topW` included only for the merge), monotonic `mergeExWeight(S,id,weight,date)` (strictly heavier wins, never lowers, date is the weight's own date), and Record/e1RM detection. Sheets and Workout become thin callers; `import-csv.js:536` now reuses the same `heaviestForEntry` + `mergeExWeight` so history import cannot drift. The phantom arg is deleted. Consequence: one place to change how a session is judged or how a Best is remembered, and tests cross the same seam users do (pure helpers + real-store smoke).
